## 提交方式

本次考核默认你已经学会了如何进行 git 开发并熟练掌握了 git 开发规范，因此我们不通过群聊收文件，**你的仓库就是唯一答卷**。

### 1. 建仓与授权

- 在**你的 GitHub 账号**下创建一个**私有**仓库，命名为 `qz2026-<你的ID>`（例：`qz2026-ZhangSan`）；
- 进入仓库的 Settings → Collaborators → Add people，将考核组账号 `lkjing2021345` 添加为协作者并等待其接受，这是评分的唯一通道，没有授权的仓库将无法被批改；
- 仓库全程保持私有，截止前不得将内容转载至其他平台或设为公开。

### 2. 仓库结构（建议）

- `README.md`：简要说明；
- `written.md`：选择题 + 简答题答案；
- `q2/`、`q3/`：各编程小题独立目录；
- `project/`：难题项目，内含 README，说明项目功能、依赖与运行方式。

### 3. 提交要求

- **全仓库**：配置好 `.gitignore`，不得提交 `__pycache__/`、`.idea/`、`venv/` 等无关产物；提交信息应能说明本次改动内容，禁止全篇 `update`；
- **简单题与中等题**：无需开分支，直接提交至 main 即可；请保持过程性提交（一题或一小步一个 commit），最后一次性上传全部内容将无法获得过程分；
- **难题项目**：请在功能分支上开发，完成后通过 Pull Request 合并回 main（自行审阅、自行合并即可，考核组不参与 review）；
- 考核期间请勿 force push 改写已推送的历史。

### 4. 交卷

- 假期内可随时推送与修改你的答案，我们只在截止后统一批改；
- 以 **10月7日 23:59** 时仓库的最后状态为准，此后请勿再推送，截止后的提交将不被查看；
- 建仓并完成协作者授权后，请尽快将仓库链接填入下方表单，便于考核组核对授权情况；
- 未完成的题目也请保留过程提交，过程同样是分。

### 5. 关于批改

- 考核期间不会有人对你的代码给出修改意见，请独立完成；
- 你的提交历史、分支结构与代码本身同等重要，均会纳入评分；
- 对题目有疑问请在**题库仓库**提 Issue（注意不要贴出你的解答代码），共性问题我们会不定期汇总置顶。（注：截至时间前**5个小时**，即10月7日21点之后的 issue 不予回复）
